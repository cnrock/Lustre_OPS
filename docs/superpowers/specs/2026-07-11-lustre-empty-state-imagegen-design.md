# Lustre OPS 克制型 ImageGen 空状态视觉设计

日期：2026-07-11

## 目标

为 Lustre 并行文件系统监控运维控制台增加少量、专业、业务相关的位图视觉素材。素材只用于没有可展示业务数据的空状态，不进入监控首屏、告警列表或核心指标区域，不降低运维信息密度。

## 视觉原则

- 使用浅灰白背景、深蓝设备结构、青色数据流和少量绿色健康状态。
- 采用简洁技术插画风格，强调 Lustre 存储节点、日志流、知识索引和集群拓扑。
- 不出现人物、文字、品牌 Logo、水印、乱码、发光球体、装饰性渐变背景或夸张 3D 场景。
- 插画在页面中仅作为辅助信息，展示高度控制在 96–120px，不替代标题、说明和操作按钮。
- 功能按钮和导航图标继续使用 Lucide，避免位图图标破坏现有图标体系。

## 素材与接入位置

### 1. 日志正常状态

- 文件名：`lustre-logs-healthy.webp`
- 接入位置：AI 日志分析的“需关注日志”列表为空时。
- 显示条件：当前视图为需关注日志，且 WARN、ERROR、FATAL 过滤结果为 0。
- 画面语义：Lustre 存储节点、平稳数据流和健康确认信号。
- 不显示条件：搜索无匹配结果时继续使用普通搜索空状态，避免把“无匹配”误解为“系统健康”。

### 2. 知识库空状态

- 文件名：`lustre-knowledge-empty.webp`
- 接入位置：智能体知识库中人工经验和上传文档均为 0 时。
- 显示条件：知识库请求成功，`caseCount + documentCount === 0`。
- 画面语义：运维手册、知识片段、向量索引节点等待内容进入。
- 保留操作：上传文档、刷新、重建索引和关闭按钮保持原有真实行为。

### 3. 巡检无异常状态

- 文件名：`lustre-inspection-clear.webp`
- 接入位置：集群健康检查“详细发现”区域。
- 显示条件：巡检已完成且 `findings.length === 0`。
- 画面语义：MDS、OSS、客户端组成的简化集群拓扑和健康通过信号。
- 不显示条件：存在任何告警或失败发现时，只展示真实发现列表。

## 工程方案

- 使用内置 ImageGen 生成三个独立位图，不要求透明背景。
- 原始生成结果复制到工作区后转换为 WebP，并限制适合 UI 的像素尺寸和文件体积。
- 最终文件存放在 `app/public/visuals/`，通过现有 `BASE_URL` 兼容 `/lustre-ops/` 子路径部署。
- 新增可复用的轻量空状态图片组件，提供固定尺寸、`alt` 文本和 `onError` 降级。
- 图片加载失败时隐藏位图并显示现有 Lucide 图标，不影响文字、按钮和业务操作。
- 不新增运行时依赖，不调用前端图片生成 API，不向浏览器暴露任何密钥。

## 状态与交互

- Loading 状态仍优先于空状态，不在数据加载过程中提前展示插画。
- Error 状态使用现有错误提示，不用健康或空数据插画掩盖错误。
- Success/Empty 状态根据真实接口数据判断。
- 图片本身不可点击，不增加无意义交互。
- 页面刷新、筛选变化和巡检结果变化后，插画随真实状态自动出现或消失。

## 验收标准

- 三张素材均无文字、乱码、Logo 和水印，视觉风格统一。
- WebP 文件可正常加载，文件加载失败时 Lucide 降级可见。
- 日志正常、知识库为空、巡检无发现三个条件分别准确触发。
- 有异常日志、已有知识数据、存在巡检发现时不显示对应空状态插画。
- 1920×1080、1440×900 和窄屏页面中无溢出、遮挡或布局跳动。
- 前端 lint、TypeScript 构建、远程构建、浏览器控制台和网络请求验收通过。

## 不在本次范围

- 不生成登录页背景、报告封面、产品 Logo 或应用图标。
- 不替换导航、按钮和状态图标。
- 不改动告警、巡检和日志的后端业务判断。
- 不创建 Git 提交，不同步 GitHub，等待用户在测试服务器实际验收后再处理版本发布。
